# APP 协议服务端适配设计

## 背景
- App 依赖 `index.json` 清单作为唯一入口，直接消费内容地址。
- 服务器现有 API 采用 Basic Auth 且返回内部字段，无法直接被 App 使用。
- 目标是在不改 App 的前提下，让服务端输出 App 协议。

## 目标与范围
- 新增只读 public 协议层，输出 `index.json` 与资源直链。
- 继续使用同一账号密码（与后台一致）进行校验。
- 保持后台/上传/管理接口不变。
- 不做：App 端改造、HTML→Markdown 转换、复杂签名鉴权。

## 协议定义
- `GET /public/index.json`：输出清单 `{ items: [...] }`。
- `GET /public/videos/{id}/download`：视频下载（支持 Range）。
- `GET /public/videos/{id}/cover`：视频封面。
- `GET /public/docs/{id}/download`：文档下载（HTML）。
- 鉴权：Basic Auth；public 兼容 `user/pass` 查询参数。

## 字段映射
- `id`：数据库主键。
- `type`：视频 `video`；文档 `article`。
- `title`：视频 `filename`；文档 `title` 优先，其次 `filename`。
- `url`：资源下载直链。
- `cover`：视频封面直链（缺失则为空）。
- `published_at`：使用 `created_at`。
- 视频仅输出 `status=ready` 且文件存在；文档仅输出文件存在的记录。

## URL 生成策略
- 如果请求使用 `user/pass` 查询参数鉴权，则在清单中生成带相同查询参数的资源 URL。
- 否则在清单中生成包含 `user:pass@host` 的资源 URL（同一账号密码）。

## 数据流
1. App 配置 `index_url`。
2. 请求 `index.json`，服务端校验账号密码并输出清单。
3. App 访问清单中的 `url/cover` 获取内容与封面。

## 错误处理
- 鉴权失败返回 401。
- 记录不存在或文件缺失返回 404。
- 未就绪视频不进入清单。

## 验证要点
- 清单字段完整、排序正确。
- 鉴权通过后可访问清单与资源。
- Range 下载返回 206。
