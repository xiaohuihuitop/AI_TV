## 2026-08-29 手机端视频自动全屏
- 结果：视频播放后按实际画面方向自动全屏，横屏自动横向、竖屏保持竖向；保留手动全屏按钮。
- 完整性：播放器固定使用 `contain`，不会为了铺满屏幕裁切或拉伸视频。
- 验证：服务器现有 480x270 横屏视频和 1080x1920 竖屏视频均在 MuMu 模拟器完成自动全屏实测。
- 限制：没有宽高且封面不可读取的非标准清单条目无法自动判断方向，但仍可正常播放并手动全屏。

## 2026-08-29 全屏视频常驻导航
- 结果：播放器改为页面级沉浸式全屏，视频完整缩放到独立操作栏上方，底部常驻“上一个、返回、下一个”。
- 交互：切换视频时按新视频方向自动旋转；队列首尾按钮正确禁用；页面返回和系统返回均恢复竖屏及系统栏。
- 根因修正：App-Plus 必须先锁定方向再隐藏系统栏；相反顺序会使横屏播放器 WebView 从 1080px 高坍缩到 240px。
- 稳定性：原生系统栏恢复失败后可再次清理，方向切换失败不会退出页面沉浸布局；宽屏设备不受全局 `720px` 内容宽度限制。
- 验证：8 个 Node 回归脚本通过；HBuilderX 5.07 编译产物已同步；MuMu 完成异常系统栏遗留、横屏、竖屏、双向切换、页面/系统返回、前后台切换和真实离线文件播放实测。
- 部署教训：本地编译完成不代表模拟器已加载新包；出现源码与界面不一致时，应直接检查设备端 `app-service.js` 是否包含本次修改。
- 调试备注：HBuilderX CLI 完整同步后的首次自动拉起曾出现一次调试基座 `WeexPlus` 内部异常和空白页，重启基座后恢复，后续播放器验收未复现。
- 残余风险：实体异形屏和系统最大字体尚未专项实测。

### 2026-09-01 HTTPS 反代资源地址修复
- 根因：服务端公共清单使用 `request.base_url`，未读取反代的 `X-Forwarded-Proto`，导致线上资源 URL 使用 `http://`。
- 修复：公共清单现在接受首个合法的转发协议并保留反代 `Host`，本地回归已确认视频和封面 URL 在 HTTPS 反代下均为 HTTPS。
- 发布要求：线上必须重新加载包含该修复的服务端镜像；当前公网仍是旧镜像，清单里的 HTTP 地址不会自动改变。
