### 2026-09-01 HTTPS 反代资源地址修复
- 根因：服务端公共清单使用 `request.base_url`，未读取反代的 `X-Forwarded-Proto`，导致线上资源 URL 使用 `http://`。
- 修复：公共清单现在接受首个合法的转发协议并保留反代 `Host`，本地回归已确认视频和封面 URL 在 HTTPS 反代下均为 HTTPS。
- 发布要求：线上必须重新加载包含该修复的服务端镜像；当前公网仍是旧镜像，清单里的 HTTP 地址不会自动改变。

## 2026-09-12 手机预览播放效果与 Range 媒体类型
- 结果：后台手机预览现在会明确显示横屏或竖屏、视频原始尺寸、“完整显示，不裁切”，并解释视频区与 76px 底部三按钮操作栏的独立关系；横竖屏模型在本地浏览器按 `1920 × 1080` 和 `1080 × 1920` 两种记录完成视觉验收。
- 根因：`StreamingResponse` 的 Range 分段响应未指定媒体类型，导致 206 响应只有范围相关头，浏览器无法将该分段稳定识别为 MP4，从而触发预览播放器错误。
- 修复：后台 `/api/videos/{id}/download` 与手机客户端使用的 `/public/videos/{id}/download` 均显式响应 `video/mp4`，无 Range 响应也声明支持字节范围；新增回归同时覆盖两个接口的 206 头和响应体。
- 残余风险：公网尚未部署本次服务端代码；部署后如单个视频仍不能播放，应使用服务器上的 `ffprobe` 检查该视频是否采用浏览器不支持的编码。

## 2026-10-03 后台预览无法点击播放的根因与修复
- 结果：build-v1.12 部署后后台"手机预览"点击播放无反应，根因是空错误层未真正隐藏——`.mobile-preview-error` 的 `display: grid` 覆盖了 `hidden` 属性的浏览器默认 `display: none`，使带 72% 黑色背景的遮罩覆盖整个视频区并拦截点击。补充 `.mobile-preview-error[hidden] { display: none; }` 后恢复。
- 验证方式：服务端接口层先全部排除（`/api`、`/public`、两种认证、多种 Range、两个视频均返回正确 206/200 与 `video/mp4`，视频 2 为 H.264 可解码）；再用真实浏览器复现：`elementFromPoint` 证明播放按钮中心命中的是错误段落；注入修复规则后按钮恢复命中且播放推进到 3.4 秒。
- 教训：接口测试全部通过时，播放故障应优先排查界面遮挡（hidden 被作者样式覆盖是典型模式）；代码库中 `.upload-progress[hidden]` 已是正确范本。
- 残余风险：手机 App 端服务端协议实测全部正常且未推送新 WGT，若部署 build-v1.13 后手机仍无法播放，需按具体症状继续定位。

### 2026-10-03 缓存导致修复不可见
- 结论：v1.13 的 CSS 修复已上线但被浏览器启发式缓存挡住，页面仍加载旧样式；`document.styleSheets` 检查确认无新规则，绕过缓存后预览播放立即恢复。服务端静态资源现已统一 `Cache-Control: no-cache`（ETag 协商），随 build-v1.14 发布。

### 2026-10-03 手机端播放根因与三端验证
- 结论：手机 App"打不开视频"的根因是云打包 APK 缺少 VideoPlayer 原生模块（manifest 未声明），与服务端无关；修复 manifest 后经 MuMu 模拟器标准基座实测，App 对服务端视频真实播放成功。
- 验证链：服务端 HTTP 层（curl 多形态 Range）→ 真实浏览器（管理端预览真实点击播放）→ WSL 本地环境（上传/识别/Range/缓存策略/浏览器播放）→ MuMu 模拟器（标准基座播放真实视频）。四层全部通过。
- 教训：uni-app 云打包必须为用到的原生组件声明 modules；播放类故障要按"接口 → 页面 → 打包模块"分层排查；HBuilderX CLI 可在模拟器中自动化复现原生模块问题。
