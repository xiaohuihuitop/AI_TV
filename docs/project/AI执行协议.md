# AI 执行协议

## 适用范围
- 本协议适用于项目全周期内的 AI 协作与输出。
- 任何执行动作前必须先遵守本协议。

## 必读文件（按顺序）
1. `项目总览.md`
2. `需求.md`
3. `计划.md`
4. `进度.md`
5. `总结.md`
6. `..\..\ai_knowledge.md`

## 硬性条款（仅以下 4 条）
1. 未读必读文件不得执行任何修改，只能提问补充信息。
2. 信息不足或冲突必须先澄清，禁止自行假设。
3. 任何变更必须写入对应文档记录（需求/计划写入“变更记录”；进度追加到 `进度.md`；总结按阶段补齐）。
4. 关键问题解决后必须写入 `ai_knowledge.md`，并在 `项目总览.md` 的“知识沉淀链接”登记。

## 推荐执行流程
1. 读取必读文件并确认当前状态。
2. 明确本次任务范围、成功标准与约束。
3. 如信息不足，先提问，禁止盲改。
4. 给出简明计划与风险评估。
5. 执行变更并自检结果。
6. 更新相关文档并记录变更。

## 推荐输出结构（建议遵循）
- 已读文件：
- 本次目标：
- 变更摘要：
- 风险/阻塞：
- 需确认问题：
- 下一步建议：

## 标准输出示例
```
已读文件：
- docs/project/项目总览.md
- docs/project/需求.md
- docs/project/计划.md
- docs/project/进度.md
- docs/project/总结.md
- ai_knowledge.md

本次目标：
- 完成 X 模块的需求细化

变更摘要：
- 更新 需求.md 的“范围与不做”与“验收标准”
- 进度.md 追加 2026-02-02 的进度记录

风险/阻塞：
- 需求目标与现有技术栈有冲突，需确认

需确认问题：
- 是否接受 A 方案的性能折中？

下一步建议：
- 明确技术选型后补充计划与里程碑
```

## 违规处理
- 未读必读文件：不执行任何修改，仅返回需补充信息清单。
- 信息不足或冲突：必须先澄清，禁止自行假设。
