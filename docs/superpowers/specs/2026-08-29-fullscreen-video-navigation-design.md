# 手机端全屏视频导航设计

## 背景

手机端播放器已支持按视频方向自动进入原生全屏，并使用 `contain` 保证画面不被裁切。但原生全屏由 Android 视频控件接管，页面中的“上一个、返回、下一个”按钮不会进入全屏层。目标用户以长辈为主，三个按钮需要始终可见，且不能遮挡或裁切视频。

## 已确认方案

采用页面级沉浸式全屏，替代 `VideoContext.requestFullScreen` 原生全屏：

- 按视频宽高或封面方向锁定横屏或竖屏。
- 隐藏系统状态栏和播放器页面的原生导航栏。
- 页面使用上下两块独立区域：视频占据剩余空间，底部操作栏固定显示三个大按钮。
- 视频继续使用 `object-fit="contain"`，允许出现黑边，不裁切、不拉伸。
- 操作栏会牺牲少量视频显示面积，但不会覆盖任何视频内容。

未采用的方案：

- 原生全屏上绘制 Native View：按钮会覆盖视频，不符合已确认布局。
- 点按画面后显示按钮：增加操作步骤，不适合长辈使用。
- 用不透明覆盖层模拟独立区域：实际仍会遮挡视频底部内容。

## 页面结构与行为

播放器页面改为自定义导航样式。进入页面后仍按现有流程加载播放队列和判断视频方向；视频开始播放且方向已知时，进入沉浸式页面并锁定方向。

沉浸式页面包含：

1. 视频区域：填满操作栏之外的可用空间，保留原生播放、暂停、进度和音量控制。
2. 操作栏：从左到右固定为“上一个、返回、下一个”，按钮提供大触控区域和高对比度文字。
3. 安全区：底部操作栏包含 `safe-area-inset-bottom`，避免被系统手势区域遮挡。

交互规则：

- “上一个”和“下一个”沿用当前播放队列；到达队列首尾时禁用对应按钮。
- 切换视频时保持沉浸式状态，并按新视频方向更新屏幕方向。
- “返回”和 Android 系统返回键均退出播放器页面。
- 页面卸载、返回或异常退出时，解除方向锁定并恢复系统状态栏。
- 禁用视频组件自带的原生全屏按钮，避免进入无法显示自定义操作栏的原生全屏层。

## 状态与生命周期

页面维护“是否处于沉浸式状态”和“当前锁定方向”。进入沉浸式状态的动作必须幂等，重复播放事件不能重复切换系统 UI。方向变化只在目标方向改变时执行。

清理逻辑集中为一个可重复调用的方法，并由页面返回、`onUnload` 等生命周期共同调用，确保：

- `plus.screen.unlockOrientation()` 被调用；
- `plus.navigator.setFullscreen(false)` 恢复状态栏；
- H5 或不支持 HTML5+ 的运行环境保持普通页面布局，不调用不存在的原生 API。

## 错误处理

- 视频方向未知时先正常播放，不盲目锁定方向；后续取得元数据后再进入沉浸式状态。
- 原生方向或状态栏 API 调用失败时保留当前播放器页面和底部按钮，不中断视频播放。
- 视频地址或播放错误沿用当前错误提示，不新增静默兜底。

## 验收标准

- 横屏视频自动进入横向沉浸式播放，三个按钮始终位于视频区域下方。
- 竖屏视频自动进入竖向沉浸式播放，三个按钮始终位于视频区域下方。
- 视频画面完整显示，无裁切、拉伸或按钮遮挡。
- 上一个、返回、下一个均可点击，首尾按钮禁用状态正确。
- 切换视频后保持沉浸式播放，并根据新视频方向正确旋转。
- Android 系统返回键和页面“返回”均能退出，退出后状态栏及屏幕方向恢复正常。
- 320dp、360dp、600dp 和横屏尺寸下按钮文字不溢出、不重叠。
- 现有离线视频、本地优先播放和播放队列行为不回归。

## 验证计划

- 为沉浸式状态切换、方向映射和清理行为增加可执行回归测试。
- 运行现有 Android 响应式布局与自动全屏回归脚本。
- 在 MuMu 模拟器分别验证横屏、竖屏视频、上下条切换、首尾禁用和系统返回键。
